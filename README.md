Я выбрал данный датасет (Rain in Australia), потому что в нем много признаков, несбалансированные классы, есть много пропусков в значимых признаках. основная метрика оценки качества классификации будем использовать PR-AUC, поскольку классы несбалансированы, 

## Гипотезы

- При заполнении пропусков средним значением в признаках ['Sunshine', 'Evaporation', 'Cloud9am', 'Cloud3pm'], PR-AUC будет больше, чем при отсутствии этих признаков 
- Sunshine, Humidity3pm, Cloud3pm, Rain Today окажутся самыми важными признаками в логистической регрессии 
- Удаление сильно коррелированных признаков между собой (|corr| > 0.9) приведет к увеличению PR-AUC
- Удаление признаков слабо коррелированных (|corr| < 0.15, будем оставлять признак с наибольшей корреляцией с таргетом)с таргетом признаков приведет к улучшению PR-AUC
- Удаление строк с пропусками в признаках Sunshine, Evaporation, Cloud9am, Cloud3pm позволит получить более высокий PR-AUC, чем заполнение пропусков средними значениями.
- Log Reg покажет себя лучше (PR-AUC будет больше), чем дерево с подобранными гипермараметрами и порогом
- При L1 регуляризации мы получим лучший результат
